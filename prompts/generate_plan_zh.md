# 提示词 · 生成计划 `generate_plan`

> 作用：跑者档案 + 所选教练包 + VDOT → 生成/再生成一份 HTML 训练计划。
> 前置：已有 `runner_profile.yaml`；需要换目标/教练/重排时发送。整段发给 AI 即可（把 `<...>` 换成实际路径）。

```
[生成计划] 今天是 <月/日>。请为跑者生成/再生成一份训练计划（HTML 看板）：

1. 读跑者档案 <RUNNER_PROFILE.yaml>，确认 A 赛、非 A 赛与 role、每周可跑日/次数/长距离日/质量日、PR 成绩（schema 见 docs/08）。
2. 加载所选教练 skill：读 `.agents/skills/coach-<档案 coach 字段>/SKILL.md`，再按档案语言读 `references/coach-<coach>_<lang>.md` 全文并遵守它；若档案与教练包不适配，先说明并建议换包，得到我确认再继续。
3. 用档案 PR 求当前 VDOT（docs/09 / scripts/vdot.py），把 E/M/T/I/R 配速写进计划第七章「配速与心率区间」。
4. 从 A 赛倒推周期，铺周骨架与逐周课表（基础→质量→巅峰→taper），遵守教练包与通用安全层（docs/03/05/06）：非 A 赛按其 role 并入当周课，只有一个全力跑的 A。
5. **逐周课表必须做成「日历」形式**：按阶段分组、每周一行，列固定为「周 ｜ 周一…周日 7 列 ｜ 合计」——
   七天全列，**休息日也要显示「休息」**，不要只列有课的那几天；每格首行写日期（如 `8/4`），下面写当天内容，
   力量日写明部位与分期（建立/转化/减停）、比赛或闸门标注用 tag。合计列只含跑步距离，力量与休息不计。
6. 把闸门与红线落到具体日期，含"峰值长距离不达标则比赛日保守起跑"的否决项。
7. 产出自包含 HTML（十章结构、章节与命名参照 examples/plan.example.html；零外链，图表用原生 canvas），第十章写"本文件为宪法"那句与已知裁决表，版本记录追加 v1 与依据。
8. 输出时列出自检清单：档案一致、无自造配速、只有 1 个 A、跑量曲线守上限、逐周表七天齐全、周量数组与合计列一致、版本已记录。
9. 回复 ≤400 字：A 赛与目标、VDOT、每周骨架、峰值周量、需要我注意的 1-2 件事。
```
