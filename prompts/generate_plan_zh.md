# 提示词 · 生成计划 `generate_plan`

> 作用：跑者档案 + 所选教练包 + VDOT → 生成/再生成一份 HTML 训练计划。
> 前置：已有 `runner_profile.yaml`；需要换目标/教练/重排时发送。整段发给 AI 即可（把 `<...>` 换成实际路径）。

```
[生成计划] 今天是 <月/日>。请为跑者生成/再生成一份训练计划（HTML 看板）：

1. 读跑者档案 <RUNNER_PROFILE.yaml>，确认 A 赛、非 A 赛与 role、每周可跑日/次数/长距离日/质量日、PR 成绩（schema 见 docs/08）。
2. 确认**跑者有哪些额外传感器**（心率带 / 跑步动态传感器·跑步豆 / 功率计）——它决定有哪些高阶数据可用
   （左右平衡、呼吸率、触地时间、垂直振幅、功率）。**先自己从 Garmin 数据里认**（心率带独有：左右平衡、
   呼吸率、着地时间占比；FIT 里还会多出 `source_type=antplus` 的配对设备），**认不出就直接问我**戴了什么、
   从哪天开始。结论写进档案，并据此决定计划里用哪些指标做追踪——**没有对应传感器，就不要在计划里引用这些指标**。
   若跑者**有配件但历史数据"带/不带"混用**：第七章「配速与心率区间」的心率区间必须建在**戴带的**数据上；
   HRmax / 乳酸阈若来自无带数据 → 标为**待复核**，在计划里写明"需一次带测校准"，不要当成既成锚点
   （**只有手表**的跑者不适用这条——单一来源，偏差恒定，趋势照样成立）。
3. 加载所选教练 skill：读 `.agents/skills/coach-<档案 coach 字段>/SKILL.md`，再按档案语言读 `references/coach-<coach>_<lang>.md` 全文并遵守它；若档案与教练包不适配，先说明并建议换包，得到我确认再继续。
4. 用档案 PR 求当前 VDOT（docs/09 / scripts/vdot.py），把 E/M/T/I/R 配速写进计划第七章「配速与心率区间」。
5. 从 A 赛倒推周期，铺周骨架与逐周课表（基础→质量→巅峰→taper），遵守教练包与通用安全层（docs/03/05/06）：非 A 赛按其 role 并入当周课，只有一个全力跑的 A。
6. **逐周课表必须做成「日历」形式**：按阶段分组、每周一行，列固定为「周 ｜ 周一…周日 7 列 ｜ 合计」——
   七天全列，**休息日也要显示「休息」**，不要只列有课的那几天；每格首行写日期（如 `8/4`），下面写当天内容，
   力量日写明部位与分期（建立/转化/减停）、比赛或闸门标注用 tag。合计列只含跑步距离，力量与休息不计。
7. 把闸门与红线落到具体日期，含"峰值长距离不达标则比赛日保守起跑"的否决项。
8. **在第四章「周期结构」内加「里程碑表」**（docs/05 §2 第 8 步、§4 章表）：里程碑是**成就点**，
   与闸门（**决策点**）性质不同——**未达成只记录、不自动改计划**。每项须写目标周/日期 ＋
   **可从数据核验**的判定标准（不许出现"感觉变强了"这类）；**前密后疏**（起点跑量越低越前密）；
   起点低的跑者要有**一致性/健康类**里程碑（如"连续 3 周完成度 ≥90%"），不要清一色成绩指标。
9. 产出自包含 HTML（十章结构、章节与命名参照 examples/plan.example.html；零外链，图表用原生 canvas），**图表须支持鼠标悬停查看当周具体数值**（`.ctip` 自包含 tooltip，不引任何外部库；未悬停时不显示）。第十章写"本文件为宪法"那句与已知裁决表，版本记录追加 v1 与依据。
10. 输出时列出自检清单：档案一致、无自造配速、只有 1 个 A、跑量曲线守上限、逐周表七天齐全、周量数组与合计列一致、**图表可悬停读值**、**里程碑表在位（每项可从数据核验、且与闸门分开）**、版本已记录。
11. 回复 ≤400 字：A 赛与目标、VDOT、每周骨架、峰值周量、传感器结论、需要我注意的 1-2 件事。
```
