# 操场间歇课：原理与口径（`track-workout` 技能参考）

> 本文件是**能力说明**，不是训练方法论。方法论来自跑者档案所选教练包。
> 生成课表用的脚本：`scripts/garmin_track_workout.py`；数据格式：`docs/02` §3b。

## 1. 为什么不能用普通跑步课

普通跑步课按 **GPS / 时间**度量。真实跑道的单圈**并非恰好 400 m**——常见 390–420 m，
而且同一跑道的测量也会随道次变化。于是：

- "2 圈 = 800 m" 的课，实际距离会在每圈累积误差；
- 手表算出的**配速**因此系统性失真（这是 docs/02 §6 的数据坑之一）；
- 组间休息的**慢跑**会把休息段混进距离与配速统计。

Garmin 的解法是**计圈键**：把步骤的结束条件设为 `lap.button`，**每次按键即记一个标称距离**。

```
{ "stepType": {"stepTypeId": 3, "stepTypeKey": "interval"},
  "endCondition": {"conditionTypeId": 1, "conditionTypeKey": "lap.button"},
  "endConditionValue": 1000.0 }
```

`endConditionValue` 对 `lap.button` 无实际语义（Garmin 存 1000），距离由按键次数决定。

## 2. 跑者在表上只需记一件事

> **每 400 m 按一次计圈键；休息结束时再按一次。**

于是：热身 5 次按键 = 2 km；每组 3 次按键 = 1.2 km；一次按键 = 一个标称 400 m。
跑道的真实圈长不再进入计算。

## 3. 步骤类型与结束条件（DTO 映射）

建课 DTO 的 ID 由 `workout://reference/structure`（MCP resource）给出，别背错：

| stepTypeId | key | 用途 |
|---|---|---|
| 1 | `warmup` | 热身段 |
| 2 | `cooldown` | 冷身段 |
| 3 | `interval` | 主课/重复段 |
| 4 | `recovery` | **活动恢复**（慢跑） |
| 5 | `rest` | **完全休息**（静止不动） |
| 6 | `repeat` | 重复组（`RepeatGroupDTO`） |

| conditionTypeId | key | 用途 |
|---|---|---|
| 1 | `lap.button` | **按计圈键**（本技能的核心） |
| 2 | `time` | 按秒数 |
| 7 | `iterations` | 重复次数（`RepeatGroupDTO` 必填） |

`RepeatGroupDTO` 必须带 `numberOfIterations` **和** `endCondition{7, iterations}`——
漏掉 `conditionTypeId` 会让 Garmin 静默改坏重复次数。

## 4. 休息方式：本技能最容易错的一处

| 实际情况 | 用 | 说明 |
|---|---|---|
| 站着不动、走两步、拉伸 | `rest`（5） | **默认**。间歇课绝大多数是这种 |
| 慢跑把心率压下来 | `recovery`（4） | 只有跑者明确说"组间慢跑"才用 |

写反的代价：手表在休息段催你跑，或者在本该慢跑时让你站住。

**同时要问清楚"组间隔多久"和"热身后那次长休息多久"**——两者往往不是一个值
（例：热身后 6 min，组间 3 min）。

## 5. 解析历史操场课（复盘口径）

以实际活动明细为准，**不要用整场平均**：

1. **分段 = 计圈按键**。一段 ≈ 一个标称 400 m。历史数据里 Garmin 可能把它记成 0.41 km
   （GPS 读数），**忽略这个数字**，只看段内时间。
2. **识别休息段**：距离骤降到 0.02–0.15 km **且**移动时间远小于总时间（基本停走）。
   若休息是慢跑，距离会明显更大——这也是判断 `rest` vs `recovery` 的旁证。
3. **成组**：每组 1.2 km = 连续 3 段；每组 800 m = 连续 2 段。
4. **判定只用段内时间**对标称距离（如 400 m 目标 1:52–2:02），**不做 GPS 换算**。
5. **心率只在组内看**：区间目标针对重复段；休息段心率不参与判定。

## 6. 替换与幂等

- 脚本按 **课名 ＋ 内容指纹** 做幂等。`--dry-run` 逐课打印判定：`create` / `reuse` / `replace` ＋原因。
- **处方变了直接重跑**（把 `6×1.2k` 改成 `5×1.2k`、改休息方式、改热身…都算）。脚本会比对
  指纹发现不一致，自动 **建新课 → 排新课 → 删旧课**。**不必再手工换课名**——那是旧版本用来
  绕开"同名复用旧课"的土办法，代价是课库留下一堆名字。
- 顺序是**先建后删**，所以中途失败也不会把手表弄空。**课被删后其日历条目会自动消失**，
  不必手动 `unschedule_workout`（而且那个工具要的是 `scheduled_workout_id`，容易传错）。
- **替换只比语义**（时长、心率靶、步骤结构），**不比 description**——描述由服务端生成，
  比它会导致每次推送都重建。
- 建完课脚本会**自动回读日历核对**（`get_scheduled_workouts`）。Garmin 日历**最终一致**：
  紧随一次"建+删"之后可能仍显示旧课，所以回读带重试。要人工核对可用
  `get_workouts` / `get_workout_by_id` / `get_scheduled_workouts`。
