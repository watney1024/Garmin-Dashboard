# 04 · 总结既往训练（写给 AI agent）

生成/更新计划与周复盘之前，先做**可靠的既往总结**。目标：用客观数据回答
"这个跑者现在处于什么状态、上阶段做对了什么/错了什么"。

## 1. 数据准备（先保证主表是新的）

1. 有 MCP 工具：`get_activities` 分页拉全量（start/limit=100，不足 100 或空则停，页间睡 ~0.3s）→ 重建 `Activities.csv`（16 列规范格式）。
2. 对最近新增活动：`download_activity_file` 按 ID 下载到 `inbox/activity_<id>.csv`（脚本已处理，见 docs/01）。
3. 无工具：读现有文件，并在结论里标注数据截止日期。

## 2. 客观指标怎么算（判断方法）

- **周跑量**：主表 `距离km` 求和（跑步类型）。单位守卫：>100 的行除以 1000。
- **强度判断用移动配速**：主表"平均配速"已是移动口径；看单次明细时分圈仍要剔除休息 lap（docs/02 §6）。
- **E 跑心率漂移**：挑同一课型、同距离/同温度的 E 课，比平均心率随周的变化。
- **长距离完成度**：计划长距离的实际距离/配速 vs 计划目标。

## 3. 分类与可比性（重点纪律）

- **连续跑 vs 区间课必须分开**：整场平均值只在同类之间比较。
- 区间课里休息段污染——比"完成质量"时用移动配速/分段数据。
- 同条件对比原则：**同距离 + 同温度 + 相近平均心率** 的两趟连续跑才有可比性。
- 连续跑判定：均速与最大速度差 < ~100 s/km 且距离 ≥4km，可视为"连续跑"。
- 小样本勿下结论：一两趟课不足以推断趋势；用 3 周以上窗口。

## 4. 输出物（按需）

| 场景 | 输出 |
|---|---|
| 计划生成前 | 近 8–12 周汇总：周跑量、课型分布、强度趋势、长距离/恢复周执行、力量频率；据此确定 VDOT 与起步跑量 |
| 周复盘 | 见 docs/06 四段式（三条趋势） |
| 换教练/换 A 赛 | 历史能力画像（速度端 vs 耐力端）说明为何选择/调整 |

## 5. 历史数据常见坑（写结论前自查）

- 曾把间歇课平均进"配速/步频"统计 → 全错。
- 把"恢复周跑少"简单归因节假日 → 必须对照跑者偏差原因与伤病日志。
- 用旧周期成绩推新周期 → 注明日期，>6 个月不算数（docs/09）。
- 忽略力量课对跑量耐受的支撑 → 力量频率要一并纳入画像。

## 6. 已知错误清单（看到就修正）

1. 距离单位米/公里混淆。
2. 平均心率被短促冲刺拉高误判"强度过大"。
3. 用目标 VDOT 反推"我应该跑多快"。
4. 不区分"主动减量"与"被动掉量"就下"练得不够"的结论。
