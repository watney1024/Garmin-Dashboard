# 00 · 总览：这是什么，怎么协作（写给 AI agent 与跑者）

## 1. 一句话

一个"**AI 陪练**"项目：agent 读这份仓库的规则，把跑者的 Garmin 数据变成**可执行、会自己
进化**的训练计划。跑者只负责两件事：维护 `runner_profile` + 每周说一句话。**人类不写
代码。**

## 2. 协作分工

| 谁 | 做什么 | 频率 |
|---|---|---|
| 跑者 | 说一句话（身体状态+课名，docs/03）；维护档案（docs/08）；按黄/红灯动作执行 | 每周 30 秒 |
| agent · 数据 | 拉 Garmin（docs/01）、重建主表/inbox、匹配、算完成度 | 每周一 |
| agent · 计划 | 总结既往（docs/04）→ 生成/更新 HTML 计划（docs/05） | 首次/按需 |
| agent · 复盘 | 填训练日志 6 项 → 四段式复盘 → 判黄/红 → 改计划 → 版本 vN（docs/06） | 每周 |

## 3. 数据流

```
Garmin Connect ──MCP stdio──> scripts/garmin_pull.py ──> Activities.csv + inbox/activity_<id>.csv
        runner_profile.yaml + 教练 skill(.agents/skills/) + VDOT(09) ──> plan HTML(05)
        每周复盘(06) ──> 改计划 + 版本 vN + 更新档案
```

## 5. 核心约定（所有人遵守）

- **版本号**：改计划必在计划"版本记录"追加 `vN`（改了什么+原因），递增不跳号。
- **数据刷新**：新会话有 MCP 工具就优先拉取重建；没有就标注数据截止日期。
- **标题治理**：发现 Garmin 默认标题零信息且知道课名时，用 `set_activity_name` 批量改端上标题。
- **判灯/三层数据协议/一句话模板**的权威定义在**跑者计划 HTML 的宪法章节**；本文档与
  docs 冲突时，以计划为准。
- **训练口径**（docs/05 §3）：低强度=心率权威+时间兜底；高质量=配速定区间+距离定负荷+心率
  当警报；长距离后段教练包/计划要求步频时步频优先；热季全部按心率。
- **通用安全层不可放松**（docs/03/06）：伤病单侧 ≥5=红、静息心率 +8、黄/红灯动作表……
  教练包只能加严。
