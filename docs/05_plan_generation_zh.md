# 05 · 计划生成：从档案 + 教练包 + VDOT 到 HTML 计划（写给 AI agent）

本文件定义**生成/再生成一份训练计划**的通用流程与 HTML 输出结构。方法论的"参数"来自
跑者档案（docs/08）与所选教练包（`coaches/<id>/`）；数值来自 VDOT（docs/09）。示例成品：
`examples/plan.example.html`。

## 1. 何时生成/再生成

- **首次**：档案 + 教练包就绪后（版本表记 `v1`）。
- **换 A 赛 / 换教练**：整体重排（新的大版本）。
- **VDOT 漂移 ≥1**：经周复盘确认后更新配速表（只升/降配速，不重排周期 → 小版本）。

## 2. 生成流程（固定顺序）

1. **读档案**：`runner_profile.yaml`（无档案先访谈补全，见 docs/08）。
2. **加载教练包**：`coaches/<coach>/README_{lang}.md` 全文；不适配先建议换包并征得同意。
3. **定水平与目标**：由档案 `pr` 求 VDOT（docs/09 §5）→ 得到 E/M/T/I/R 配速区间表。
   - A 赛目标：用 VDOT 等效全马/半马成绩做初值，结合耐力短板/历史做保守修正；
   - 配速永远来自**当前 VDOT**，不用目标 VDOT 反推训练配速。
4. **定周期**：从 **A 赛**倒推 N 周（时长由教练包决定，如 16/18 周）；标出非 A 赛在哪些周（role 决定跑法）。
5. **定周骨架**：教练包 §3 用档案的 `runs_per_week / long_run_day / quality_days` 装配每周期形。
6. **铺逐周课表**：基础→质量→巅峰→taper 的跑量曲线（遵守教练包 §4 与通用安全层），每课命名 `W<n> <星期> <课型> <关键>`。
7. **加防线**：教练包 §6 红线 + 通用安全层（docs/03）合入"红线与闸门"章；三闸门按 A 赛与非 A 测试赛落到具体周/日期。
8. **产出 HTML**（结构见 §4），`版本记录` 记 `v1` 及依据。
9. **自检**（§5）通过后才交付跑者。

## 3. 训练口径（对每课"按什么跑"的判定；各教练包必须遵守）

- **低强度（E/恢复）**：心率/体感是唯一权威，时长兜底；配速只当参考（VDOT E 区间当参考下限）。天热/没睡好/疲劳 → 全切"心率模式"。
- **高质量（T/I/M 段/测试赛）**：配速给区间、距离定负荷，心率当警报（异常高或漂移 → 减速）。
- **长距离后段**：若教练包/计划要求步频优先（如 ≥170）则步频 > 配速 > 心率。
- **力量**：以次数×重量为准；与跑步强度口径无关。
- 一句话：**主菜按距离定负荷、按配速验收；恢复与天气劣化时全切时间＋心率。**

## 4. HTML 输出结构（"看板"槽位）

每一份计划都是自包含 HTML（内联 CSS + 2 个 `<canvas>`）。**章节槽位固定、内容由教练包+档案填充**：

| 章节 | 内容 | 数据来源 |
|---|---|---|
| 头部 | 跑者代号、A 赛与目标、VDOT、教练包、计划周数 | 档案/VDOT/教练包 |
| 一、目标与赛历 | A/attempt/training 三档赛与其角色、非 A 赛怎么跑 | 档案 `races` |
| 二、周骨架与周期概览 | 一周 7 天角色、基础/质量/巅峰/taper 分期 | 教练包 §3/§4 |
| 三、强度体系与配速 | 区间表：区/配速/心率用途/典型课；注明"近似 VDOT 配速" | docs/09 + 教练包 §2 |
| 四、逐周课表 | `周｜日期｜各天课｜合计跑量`；非 A 赛周与恢复周特殊标注 | 流程 §6 |
| 五、跑量曲线 | `<canvas id="vol">` 周跑量柱状图 + 长距离线 | 流程 §6 |
| 六、恢复/节假日/比赛周预案 | 恢复周目的；节假日/出差降频规则；比赛周减量 | 教练包 §4 + 通用规则 |
| 七、风险红线与决策闸门 | 通用安全层 + 教练包红线；闸门表（门 1/2/3 落到具体日期） | docs/03/06 + 教练包 §5/§6 |
| 八、执行追踪与每周复盘 | 周一固定动作表、复盘四段式、计划 vs 实际表 + `<canvas id="trk">`、版本记录 | docs/06 |
| 九、辅助与力量（若档案含 strength） | 每周分布与动作底线 | 教练包 §7 + 档案 |

约定：
- 命名、图表实现、复盘协议等**结构细节以 `examples/plan.example.html` 为参照**（复制其骨架再填内容）。
- `版本记录`在文档末尾：每次改动追加 `vN` 行（改了什么 + 触发原因），递增不跳号。
- 计划第十章（在执行追踪章内）或最末章担任该跑者的"宪法"章节——当它与其他文档冲突时以它为准（由生成时写入这句话）。

## 5. 自检清单（交付前）

- [ ] 每课配速能回溯到 `data/vdot_table.csv` 或"心率/体感"口径，无自造数字。
- [ ] 周骨架与档案一致：次数、长距离日、质量日。
- [ ] 逐周跑量曲线遵守教练包与通用安全层（增幅/单次占比/恢复周）。
- [ ] 只有 1 个 A 赛；非 A 赛不威胁 A 赛（并入当周长距离或单独减量周）。
- [ ] 闸门/红线都写明了触发与动作，且含"比赛日保守起跑"类否决逻辑。
- [ ] 版本表已记本次生成依据。

## 6. 生成时不要做

- 不要臆造档案里没有的 PR/成绩；缺则让跑者补测或用现有最近成绩并标注日期。
- 不要用目标 VDOT 跑训练；不要使用与 VDOT 表矛盾的配速。
- 不要写"XX 周一定是多少公里"这种与教练包/档案冲突的硬数字。
- 计划中不出现跑者真实姓名/可识别信息之外的过度细节；示例用代号。
