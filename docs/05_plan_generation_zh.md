# 05 · 计划生成：从档案 + 教练包 + VDOT 到 HTML 计划（写给 AI agent）

本文件定义**生成/再生成一份训练计划**的通用流程与 HTML 输出结构。方法论的"参数"来自
跑者档案（docs/08）与所选教练 skill（`.agents/skills/coach-<id>/`，Agent Skills
标准）；数值来自 VDOT（docs/09）。示例成品：
`examples/plan.example.html`。

## 1. 何时生成/再生成

- **首次**：档案 + 教练包就绪后（版本表记 `v1`）。
- **换 A 赛 / 换教练**：整体重排（新的大版本）。
- **VDOT 漂移 ≥1**：经周复盘确认后更新配速表（只升/降配速，不重排周期 → 小版本）。

## 2. 生成流程（固定顺序）

1. **读档案**：`runner_profile.yaml`（无档案先访谈补全，见 docs/08）。
2. **加载教练 skill**：先读 `.agents/skills/coach-<coach>/SKILL.md`，再按档案语言读全文
   `references/coach-<coach>_<lang>.md`（`<coach>`=档案 coach 字段，`_`→`-`；
   `<lang>`=档案 language）；不适配先建议换包并征得同意。
3. **定水平与目标**：由档案 `pr` 求 VDOT（docs/09 §5）→ 得到 E/M/T/I/R 配速区间表。
   - 年龄/性别修正：档案含 `identity.birth_year`+`identity.sex` 且年龄在 18–38 之外时，
     求**年龄修正 VDOT**（docs/09 §8），训练配速用修正后值。
   - A 赛目标：用 VDOT 等效全马/半马成绩做初值，结合耐力短板/历史做保守修正；
   - 配速永远来自**当前 VDOT**，不用目标 VDOT 反推训练配速。
4. **定周期**：从 **A 赛**倒推 N 周（时长由教练包决定，如 16/18 周）；标出非 A 赛在哪些周（role 决定跑法）。
5. **定周骨架**：教练包 §3 用档案的 `runs_per_week / long_run_day / quality_days` 装配每周期形。
6. **铺逐周课表**：基础→质量→巅峰→taper 的跑量曲线（遵守教练包 §4 与通用安全层），每课命名 `W<n> <星期> <课型> <关键>`。逐周课表输出为**日历**（按阶段分组、每周一行、周一–周日 7 天全列、休息日也写"休息"）。计分制教练包（如 daniels_vdot）另设**周分目标**，质量课的量上限用 `vdot.py --session N` 查表 5-5（docs/09 §7）。
7. **加防线**：教练包 §6 红线 + 通用安全层（docs/03）合入"红线与闸门"章；三闸门按 A 赛与非 A 测试赛落到具体周/日期。
8. **加里程碑**：在第四章（周期结构）内设**里程碑表**（见 §4）。里程碑是**成就点**，与闸门（**决策点**）性质不同——闸门结果可能改计划，里程碑**未达成只记录、不自动改计划**。每项须含目标周/日期与**可从数据直接核验**的判定标准；起点跑量越低，里程碑越要**前密后疏**。
9. **产出 HTML**（结构见 §4），`版本记录` 记 `v1` 及依据。
10. **自检**（§5）通过后才交付跑者。

## 3. 训练口径（对每课"按什么跑"的判定；各教练包必须遵守）

- **低强度（E/恢复）**：心率/体感是唯一权威，时长兜底；配速只当参考（VDOT E 区间当参考下限）。天热/没睡好/疲劳 → 全切"心率模式"。
- **高质量（T/I/M 段/测试赛）**：配速给区间、距离定负荷，心率当警报（异常高或漂移 → 减速）。
- **长距离后段**：若教练包/计划要求步频优先（如 ≥170）则步频 > 配速 > 心率。
- **力量**：以次数×重量为准；与跑步强度口径无关。
- 一句话：**主菜按距离定负荷、按配速验收；恢复与天气劣化时全切时间＋心率。**

## 4. HTML 输出结构（"看板"槽位）

每一份计划都是**自包含 HTML**：内联 `<style>` + 内联 `<script>`、恰好 2 个 `<canvas>`
（`id="vol"` / `id="trk"`），**不允许任何外部依赖**（CDN、外链字体、外部脚本/样式一律不用——
计划要能离线打开、能直接打印）。图表用原生 canvas 绘制。
**章节槽位固定、内容由教练包+档案填充**：

| 章节 | 内容 | 数据来源 |
|---|---|---|
| 头部 | 5 张数据卡（距比赛 / 周期总跑量 / 周跑量峰值 / 最长单次 / 质量课频次）+ 一句话 lede（周期、目标配速、周骨架、教练包、VDOT、版本） | 档案/VDOT/教练包 |
| 一、每周骨架 | 7 天 `weekgrid`（每天角色 + 强度色块）+ 骨架说明 + 力量日/关键日为何放这天的理由 | 教练包 §3 |
| 二、关键课怎么跑 | 把这个跑者最容易跑错的课讲透（"问→答→理由"块 `.ans` + 标准做法表） | 教练包 §2 + 档案 |
| 三、与人/约束配合 | 外部教练课、跑团、力量日、交叉训练（攀岩/骑行等）怎么给跑步让位 | 档案 `constraints`/`strength` |
| 四、周期结构与跑量曲线 | 阶段表（阶段/周次/日期/周量/核心任务）+ **里程碑表**（编号 / 名称 / 目标周与日期 / 可核验判定标准 / 达成列）+ `<canvas id="vol">`：堆叠柱=周跑量（含比赛段）+ 折线=当周长距离；图例用 `.lg` | 教练包 §4 + 档案 |
| 五、逐周课表 | **日历形式**：按阶段分组、每周一行，列固定为 `周 ｜ 周一…周日（7 天全列）｜ 合计`；每格首行日期、下面是当天内容，**休息日也显示"休息"**；合计列只含跑步距离 | 流程 §6 |
| 六、恢复周与节假日预案 | 恢复周目的（为什么是这一周）；节假日/出差处置顺序；比赛周减量 | 教练包 §4 + 通用规则 |
| 七、配速与心率区间 | 区间表（区/配速/心率用途/用在哪）+ "这一课按什么跑"口径 + 年龄修正启用状态声明 | docs/09 + 教练包 §2 |
| 八、力量与辅助 | 每周分布、动作底线、与跑步的间隔、分期；辅助课（ST 等）口径 | 教练包 §7 + 档案 |
| 九、风险红线与决策闸门 | 通用安全层 + 教练包红线；`.gates` 闸门卡（门 1/2/3 落到具体日期与判定阈值） | docs/03/06 + 教练包 §5/§6 |
| 十、执行追踪与每周复盘（**宪法**） | 协作协议、**已知裁决表**（与 docs/教练包不一致处 + 复核条件）、计划 vs 实际表 + `<canvas id="trk">`、版本记录 | docs/06 |

排版元素（类名以 `examples/plan.example.html` 为准）：`.cards/.card` 数据卡、`.weekgrid/.wday` 周历格、
`.tw` 横向滚动表壳、`.note/.warn/.key/.ok/.ans` 五种色块、`.ask` 配合条目、`.phase` 阶段标题、`.gates/.gate`
闸门卡、`.chart` 图表容器、`.foot` 页脚。

约定：
- **第二、三章按跑者情况命名**（没有外部教练就换成本跑者的关键课/约束），两者可合并；其余槽位固定。
- 命名、图表实现、复盘协议等**结构细节以 `examples/plan.example.html` 为参照**（复制其骨架与 CSS 变量再填内容）。
- **第十章（执行追踪与每周复盘）就是该跑者计划的"宪法"章节**：当它与其他文档冲突时以它为准（生成时写入这句话）。
- `版本记录`在第十章末尾：每次改动追加 `vN` 行（改了什么 + 为什么 + 触发原因），递增不跳号。
- **闸门 ≠ 里程碑**：闸门是**决策点**（结果可能改计划，见第九章）；里程碑是**成就点**（未达成只记录、不自动改计划，见第四章）。两者不可互相替代：闸门少而重，里程碑前密后疏。
- 若本计划在某些量上**有意偏离**教练包上限（例如低跑量下的长距离占比），必须写进第十章的"已知裁决"表，
  写清理由与复核条件——**偏离要留痕，不能静默**。

## 5. 自检清单（交付前）

- [ ] 每课配速能回溯到 `data/vdot/` 或"心率/体感"口径，无自造数字。
- [ ] 周骨架与档案一致：次数、长距离日、质量日。
- [ ] 逐周跑量曲线遵守教练包与通用安全层（增幅/单次占比/恢复周）；恢复周后回落与比赛周不参与增幅比较，且口径写在计划里。
- [ ] 只有 1 个 A 赛；非 A 赛不威胁 A 赛（并入当周长距离或单独减量周）。
- [ ] 闸门/红线都写明了触发与动作，且含"比赛日保守起跑"类否决逻辑。
- [ ] 版本表已记本次生成依据。
- [ ] **自包含**：无任何外链（CDN/字体/图片），恰好 2 个 canvas（`vol`/`trk`），无 BOM。
- [ ] **章节齐**：一～十 十章在位；第十章带"本文件为宪法"那句话与"已知裁决"表。
- [ ] **逐周表是完整日历**：每周一行、周一–周日 7 列全在，**休息日也写"休息"**（不许只列有课的天）；每格有日期。
- [ ] **数字自洽**：`#vol` 的周量数组 == 逐周表"合计"列；`#trk` 的计划数组与之一致、实际数组长度相同且初始为空。
- [ ] **里程碑表在位**：每项都有目标周/日期与**可从数据核验**的判定标准（不许出现"感觉变强了"这类无法核验的项）；且与闸门分开——里程碑不得写成会改计划的条件。
- [ ] 若有任何有意偏离教练包上限之处，已在第十章"已知裁决"表留痕（理由 + 复核条件）。

## 6. 生成时不要做

- 不要臆造档案里没有的 PR/成绩；缺则让跑者补测或用现有最近成绩并标注日期。
- 不要用目标 VDOT 跑训练；不要使用与 VDOT 表矛盾的配速。
- 不要写"XX 周一定是多少公里"这种与教练包/档案冲突的硬数字。
- 计划中不出现跑者真实姓名/可识别信息之外的过度细节；示例用代号。
- 不要把**里程碑写成闸门**（里程碑未达成不应自动改计划）；不要设无法从数据核验的里程碑（如"跑姿变好"）。
- 不要把里程碑设成清一色的成绩指标——起点低的跑者需要**一致性/健康类**里程碑（如"连续 3 周完成度 ≥90%"、"静息心率周均不升"），否则前几周看不到任何抵达。
