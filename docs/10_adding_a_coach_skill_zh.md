# 10 · 新增一个教练 skill（写给 agent 与维护者）

coach 包让计划生成可以**即插即用不同教练理念**。任何人（通常是一个 agent 与跑者协作）
都可以按本文件新增一个包。**新增包不需要改任何代码。**

## 工作流

1. 确认理念来源与跑者是否已有**可引用的公开来源**（书目/文章/人物）。包的正文必须是
   **你自己写的概括与应用指南**，不复制原文——每个包第 1 节都要有版权声明。
2. 复制 `coaches/_TEMPLATE_zh.md`（和 `_en.md`）→ `coaches/<new_id>/README_zh.md` / `_en.md`。
   `id` 用小写蛇形：`<new_id>` 将写入跑者档案的 `coach` 字段。
3. 按固定 8 节填写。注意：
   - **配速来源**必须说明落到哪套数据上（VDOT 表 / 心率区 / 体感）——不要自造一张无出处配速表。
   - **红线与注意点**只能比通用安全层更严；通用安全层不可覆盖（docs/03、docs/06）。
   - **周骨架规则**要能被 `runs_per_week / long_run_day / quality_days` 参数化消费。
4. 在 `coaches/README_zh.md` 与 `_en.md` 的索引表各加一行。
5. 若该理念会改变"计划 HTML 的某章节内容"，在包内给出模板/示例片段；不改变文档结构。
6. 可加 `examples/` 子目录放一段示意（可选）。

## 质量门槛（agent 自检）

- [ ] 一个 agent 只读该包，就能生成符合该理念的周骨架与课表。
- [ ] 每节都有内容（不适用处明确写"不涉及"）。
- [ ] 与通用安全层无冲突，或冲突处取更严并已注明。
- [ ] 版权声明在第 1 节；正文是转写非引用。
- [ ] 有明确"适合/不适合"画像，避免误用。

## 与 docs/05 的对接

`docs/05` 描述通用生成流程：读档案 → 读所选包 → 生成 HTML 计划。每个包相当于为
流程提供"方法论参数"；如果你发现所有包都需要某个新参数（如某强度定义的阈值），
把它提升为 `_TEMPLATE` 的公共章节，而不是只写在一个包里。

## 测试

- 用 `examples/runner_profile.example.yaml` + 新包跑一次 `docs/05` 流程，人工/agent 校验
  产出的周骨架是否自洽（次数、长距离日、强度日是否符合档案）。
- 检查配速数值是否落在合理区间（与公开资料差不大于 ~10–20 s/km）。
